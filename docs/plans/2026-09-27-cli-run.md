# Plan: `hf run --issue`

**Goal**: `hf run --issue <identifier> -- <agent> [args]` resolves the Issue through the Read API, computes the
config snapshot ID locally, and launches the agent with `hf.*` resource attributes, the pinned ingest
destination, the user ingest key and `HARNESSFORCE_ISSUE`.

**Canonical spec** (lambda-script/harnessforce#22, branch `spec/agent-session-registration`):
`docs/specs/features/correlation.md` (「CLIの宛先の決め方」, 「CLI」 `hf run`, 送信先の固定, 「構成の収集」),
`docs/specs/api/read-api.md` (`GET /api/v1/issues`, `/issues/{identifier}`),
`docs/specs/api/semantic-conventions.md` (`hf.*`, repository normalization, config snapshot ID),
`docs/references/agent-telemetry.md` (`OTEL_RESOURCE_ATTRIBUTES` percent-encoding).

**Branch**: `feature/cli-run` on `feature/cli-credentials`.

Heavy commands go through `sh $HEAVY <cmd>`; turbo with `--concurrency=1`. Server endpoints do not exist,
so tests use a local `node:http` mock of apps/web.

## Decisions outside the spec (reported as spec gaps in the PR)

- Read API list body: `{"data": [{"identifier", "title", ...}], "next_cursor": string | null}`. A 200 whose
  body is not this shape is a candidate fetch failure.
- Candidate display: `Issueを解決できませんでした。候補:` then one `<identifier>  <title>` line per candidate.
- The identifier is percent-encoded as one path segment (`#45` → `%2345`). Redirects are not followed
  (the ApiToken is not sent to another host); a 3xx is "another status".
- An unreadable user settings file counts as having no `env` values (hf run then asks for `hf init`).
- `--settings` is passed only when the agent's basename is `claude` (`claude.exe`, `claude.cmd`), before the
  user's args. An existing `OTEL_RESOURCE_ATTRIBUTES` in the shell keeps its entries whose keys do not
  start with `hf.`.
- The ingest key is passed as `OTEL_EXPORTER_OTLP_HEADERS=Authorization=Bearer <key>`.
- The agent's exit code is returned; a launch failure prints `<agent>を起動できませんでした` and exits 1.

## Tasks

1. **Destinations** (`src/destinations.ts`): Read API base (env, user settings, build default), ingest endpoint
   (env, user settings), workspace ID (env, user settings), scheme rule. Terminals: `hf init`を実行してください,
   接続先のURLが不正です.
2. **Issue resolution** (`src/run/issues.ts`): `GET /api/v1/issues/{id}` then `GET /api/v1/issues?query=` on 404,
   Bearer ApiToken, 30 s limit, 10 candidates, all terminals of step 1.
3. **Launch environment** (`src/run/launch-env.ts`): `OTEL_RESOURCE_ATTRIBUTES` (percent-encoded), child env,
   `--settings` JSON with env only, `HARNESSFORCE_ISSUE`.
4. **Launch context** (`src/run/context.ts`): git VCS fields (repository via `@harnessforce/semconv`), project
   root, config snapshot ID with the 1 s budget, skip reasons that suppress `hf.agent.config_version`.
5. **`hf run` command** (`src/run/run.ts`, `main.ts`, `bin.ts`): order keychain → destinations → workspace and
   keys → identifier → resolution → snapshot → origin pin → launch. Real spawn test with a node agent.
